# 時空間 A*（Space-Time A*）

- algorithm-id: `space-time-astar`
- 調査日: 2026-07-27
- 担当: Codex

## 対象問題

既知の動的障害物または予約済み経路を避ける単一エージェント最短路探索。サイトでは one-shot MAPF の低レベル探索として使う。原論文の Cooperative Pathfinding は各エージェントの経路を順番に計画するが、時空間 A* 単体は 1 エージェントの探索であり、複数エージェントの優先順位や完全性を決めない。

サイト既定の vertex conflict と edge-swap conflict を禁止し、`forbidFollowing` が有効なら following conflict も禁止する。Silver 論文の予約表は占有領域を記述するが、edge-swap / following の用語別仕様は明記していないため、後二者はサイトモデルへの適合である。

## 原論文

- paper-id: `cooperative-pathfinding-2005`
- 参照した節: Cooperative A*
- 参照したページ: PDF p.2
- 参照した Algorithm 番号: 該当なし

## 状態表現

`(cell, time)`。`cell` は 4 近傍グリッドの通行可能セル、`time` は 0 始まりの離散時刻。

## 遷移

1 ステップで上下左右へ移動するか、その場で wait する。遷移先の `(cell, time)` が予約済みなら棄却する。サイト既定では逆向きに同じ辺を同時使用する遷移も棄却する。

## 目的関数

固定された予約表のもとで、対象エージェントの到着時刻を最小化する。MAPF 全体の sum of costs を最適化する手法ではない。

## ヒューリスティック

Silver 論文 p.2 は CA* に任意の admissible heuristic を使用でき、基本形では Manhattan distance を使うと述べる。今回の独立した Space-Time A* Solver は Manhattan distance を使う。HCA* では別途 RRA* による抽象距離を使う。

## 終了条件

ゴール状態を OPEN から取り出し、`goalBehavior: stay` の場合は予約表の確認範囲末尾までゴールを占有できるとき成功する。`disappear` の場合は到着時点で成功する。時刻上限、展開上限、タイムアウト、中断でも終了する。

## 理論保証

| 項目       | 値   | 根拠（原文とページ）                                                                    |
| ---------- | ---- | --------------------------------------------------------------------------------------- |
| 完全性     | 不明 | Silver 2005 PDF p.2 は時空間探索を定義するが、有限 horizon を含む完全性定理はない       |
| 最適性     | 不明 | admissible heuristic の記述はあるが、この名称の独立手法に対する最適性定理は確認できない |
| 準最適保証 | なし | 重み付き探索ではなく、準最適係数を使わない                                              |

### 保証が成立する条件

原論文から独立した保証としては確定しない。実装上は有限グリッド、非負単位コスト、許容ヒューリスティック、十分な時刻上限の範囲で通常の A* として最短到着を探索するが、この推論をマニフェスト上の原論文保証には昇格させない。

## タイブレーク

論文は CA* の同一 `f` 値のタイブレークを指定していない。今回の実装は `f` 昇順、同値なら `g` 降順、さらに生成順の順で決定的に選ぶ。近傍生成順は wait、up、down、left、right の順である。

## 論文中で未指定の箇所

- edge-swap conflict と following conflict の個別処理
- 有限の予約 horizon を越えた予約の扱い
- 同一 `f` 値の厳密なタイブレーク
- ブラウザ向けの展開数・時間・入力サイズ上限

## 公開実装との差異

|                          | 方式                                                                                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 論文で定義された方式     | space-time を探索し、予約表の占有領域を通行不能として扱う                                                                                                        |
| 公開実装で採用された方式 | `libmultirobotplanning` commit `4c75fa2` は汎用 A* / SIPP を CBS や prioritized planning の低レベルに組み込む。独立した Space-Time A* 実行ファイルは確認できない |
| 今回のブラウザ実装       | TypeScript の独立実装。vertex、edge-swap、任意の following 予約を検査する                                                                                        |
| 差異を選んだ理由         | サイト共通の `SimulationRules` を黙って変えず、後続の CA*/HCA*/CBS 系から再利用するため                                                                          |

## 今回の実装方針

低レベル関数を Solver UI からも実行できるようにする。Space-Time A* 自体を CA* と混同しないため、独立 Solver は 1 エージェントのシナリオだけを受理し、複数エージェントには構造化エラーで CA*/HCA* を案内する。

## 必要なテスト

- 予約セルを wait で避ける
- edge-swap と following の設定を尊重する
- ゴールを将来予約される場合に早着を採用しない
- 単一エージェントで個別最短コストを返す
- 展開上限、タイムアウト、中断、決定性
- `expand-node` / `reject-reserved-state` / `finish` と trace 上限

## 未対応機能

- 連続時間、速度、占有半径
- 外部から任意の動的障害物軌道を入力する UI
- 無限 horizon の証明付き探索
